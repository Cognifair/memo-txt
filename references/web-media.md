# 官网 APKG 中转与媒体引用回填

用于同一墨墨账号内，把 APKG 中的图片、音频经官网原生导入取得的引用，原样复用到新 TXT 卡片。不请求 OpenAPI、Cookie 或密码，不直接调用站点内部接口。不要把普通 TXT 交付或预览许可当作上传/提交许可。

## 准备

- 使用已安装的 Python Playwright 和 Chrome。普通 TXT 离线命令不依赖它们。独立 Chrome 配置默认在应用数据目录 `Memo-TXT/MarkjiBrowserProfile`，不放进技能仓库或交付品。用户已有独立配置时，可用全局参数 `--profile <路径>` 复用；不要传入日用 Chrome 的配置目录。若看到登录或验证码，交给用户处理。
- 输入是已打好的 APKG（每包严格小于 80 MB），或同账号已存在的中转牌组编辑页地址，或其「保留语法」导出的 TXT。此功能不生成 APKG、不切包。
- 中转卡第一行只写唯一编号，如 `IMG_001` 或 `AUD_001`，每卡放一个对应媒体。跨包不能重复编号，APKG 文件名也不能重复。目标 TXT 中用 `{{IMG_001}}`、`{{AUD_001}}` 标出位置；图片占位从行首独占一行。只复用导出里的完整原生 Pic/Audio 标签，不猜 ID、不改大小写。
- 确定目标牌组准确名称，优先用完整编辑页地址核对。目标由用户预先创建或明确指定；不替用户挑同名牌组。上传前确认文件和账号，提交前确认目标及范围。默认只预览；`--commit` 仅在用户明确授权自动导入时使用。

## 命令

从技能目录运行；涉及用户文件的参数用绝对路径：

```text
python -B scripts/cli.py web-media login
python -B scripts/cli.py web-media [--profile <独立配置>] run --apkg <APKG> --template <模板TXT> --target-url <目标编辑页URL> --target-name <准确牌组名> --run-dir <新结果目录>
```

- 将 `--apkg` 换成 `--source-url <中转编辑页URL>` 可跳过上传；换成 `--exported-txt <原始TXT>` 可跳过上传和导出。可重复提供同类来源。列表内也可用 `--source-name <准确中转牌组名>`；不用 `--target-url` 时按 `--target-name` 在当前列表唯一定位。以 `--library-url <牌库或文件夹URL>` 指定列表。
- `--apkg` 会真的上传并创建中转牌组，即使没加 `--commit`。当前实现按文件名识别新牌组。同名或上传结果不确定，先检查牌库，找到已有中转牌组后按地址继续；不要盲目重传。
- 脚本保存 `export-001.txt` 等原始导出、`filled.txt`（网页粘贴正文）和 `run.log`。准备粘贴时移除文件头和末尾 `===`，避免末尾标记被当作卡片正文；不改普通 TXT 文件容器的结尾规则。已生成的网页正文不是完整的 Memo-TXT 交付容器，不能直接按完整文件格式校验或冒称通过 `finalize`。
- 预览须与预计张数一致，并等待平台校验完成；默认停在此处。开启 `--commit` 后仅点击一次，重新打开目标牌组核对新增数量及题面。脚本检查当前页面可见的同题面卡片，**不是全牌组去重**。若已知本批在整牌组中的准确序号，可附 `--verify-range 24-25`（示例），只导出对应范围核对题面和媒体标签。
- 提交后等待或回读不完整，报告已证实的步骤，先只读核查，不重试。默认保留中转牌组，不删除、发布或修改来源卡片。不假定删除中转牌组后媒体仍有效，也不假定跨账号可用。

## 验收边界

已在真实官网验证自动下载含语法 TXT、按编号回填、两卡预览、提交和导出回读一致；也人工验证了图片显示及音频播放。Playwright 自动选择 APKG 文件并上传仅通过本地浏览器模拟，尚未实测从自动上传开始跑通真实官网整链。上传、题面回读、媒体标签一致、图片显示和音频播放分别报告，不互相替代。
